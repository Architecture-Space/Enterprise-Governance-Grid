# API Examples

Two layers: **(A) implemented POC surface** (`/api/kg/*` against Neo4j) and **(B) target platform APIs** for the full headless programme (Semantic / Graph / Search / MCP / Ossie). Pitch and strategy docs should not treat (B) as already shipped in this repo.

Data narrative: `tmforum.json` → `apiExamples` · machine SoT for live queries: `backend/neo4j/cypher/` + `backend/api/`.

---

## A. Implemented — KG API (Setup A)

Base URL: `http://127.0.0.1:8787` · health: `GET /api/kg/health` · read-only (writes rejected).

| Method | Call | Result |
| --- | --- | --- |
| GET | `/api/kg/health` | Neo4j ping + query catalog count |
| GET | `/api/kg/views` | Curated view list (`global-hub`, `alignment`, `natco-stack`, `product-path`) |
| GET | `/api/kg/views/:id` | Run a named view |
| GET | `/api/kg/queries` | Catalog meta (Q1–Q7, N1–N5, O1/O3) |
| GET | `/api/kg/queries/:id` | Cypher text for one demo query |
| POST | `/api/kg/queries/run` | `{ "queryId": "Q3", "params": { "productId": "dp-customer-360" } }` |
| POST | `/api/kg/run` | Ad-hoc read Cypher |

Default demo params: `productId=dp-customer-360`, `natco=natco-de`.

UI consumer: `/demo/customer360/semantics` (live) or mock snapshots on Pages.

## B. Target platform APIs (programme)

Headless calls using SID Customer / Product / CFS as the worked example. **Not** implemented as first-class routes in `backend/api/` yet — use kg-api / Cypher for POC proof.

| API | Call | Result |
| --- | --- | --- |
| Semantic | `GET /concepts/global/customer` | SID Customer definition |
| Semantic | `POST /resolve { term: 'Kunde', natco: 'de' }` | → global/customer via sameAs / federation |
| Graph | `GET /graph/neighbors/global/customer?depth=2` | Account · Product · CFS |
| Search | `GET /search?q=ProductOffering&ns=global` | Offering + Collibra Angebot |
| MCP | `semantic.lookup('customer-facing-service')` | Certified CFS URI for agents |
| Ossie | `GET /ossie/global/versions/1.0.0` | Tier A SID package export |
